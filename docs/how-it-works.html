Rovr: how it works, down to the atoms

Rovr keeps the macOS knowledge from yabai and replaces the architecture around it. It treats macOS state as untrusted, holds two models of the world, and reconciles them in a loop. This page traces that idea from the top level to the exact structs, files, and threads that carry it out, as the tree stands now.

Prime rule: never assume an OS mutation worked. Re-observe and verify. Core loop: observe, decide, execute, verify, reconcile Tests: 141 passed at last full check

1. The stack in one picture

Rust owns product logic. macOS specifics live behind one trait. The CLI holds no policy.

Platform mayEnumerate windows, displays, and Spaces. Move, resize, focus. Move windows between Spaces. Create, destroy, reorder, and focus Spaces. Set layer, opacity, sticky, shadow, scale. Subscribe to native events.
Platform must notChoose layouts. Evaluate rules. Decide workspace policy. Parse config. Own desired state. Hold product behavior. If a macOS hack is needed, it stays inside this layer.

2. The one loop that runs everything

macOS can miss events, return stale data, move windows on its own, rebuild Spaces after sleep, restart the Dock, or reject an operation. The loop below is how Rovr stays correct anyway.

macOS callback -> typed Event -> update ObservedState
  -> reconcile -> Action -> Platform -> macOS
  -> re-observe -> verify -> reconcile again
What verify means in code. After a mutation the daemon snapshots again through execute_and_refresh. If observed and desired still differ, the next reconcile emits fresh actions. No step trusts its own write.

File: crates/rovr-types/src/lib.rs. These are the smallest units the rest of the system passes around.

Typed ids instead of native pointers

Core never stores long lived Objective-C objects, Accessibility references, SkyLight pointers, or BSP node pointers. It passes small typed ids and looks up fresh data each cycle.

Geometry

Honest unknowns

5. Observed state and desired state

Files: rovr-core/src/state.rs and rovr-core/src/reconcile.rs. Two maps, one diff.

// reconcile.rs: refresh always wins over mutation
if observed.refresh_required { return vec![Action::RefreshAll]; }
// stale window -> RefreshWindow, never a blind move
// space mismatch -> MoveWindowToSpace
// frame differs by more than 0.75pt -> SetWindowFrame
// wants focus and not focused -> FocusWindow

Generations

Sleep, wake, Dock restart, and display changes call bump_generation, which sets refresh_required. The next reconcile emits RefreshAll instead of guessing. Per window checks compare window.generation against the global generation so a geometry sensitive op cannot complete on stale data.

What apply_event does on a snapshot

Workspace identity survives SpaceId churn

macOS SpaceIds are volatile. Rovr names are stable. WorkspaceState holds name, desired_display, persistent, backing_space, ordinal, last_position, and dynamic. Remap runs in sorted order every time: unclaimed spaces by position then id, workspaces by ordinal.

Resume pass

A workspace whose last_position matches an unclaimed space at the same position reclaims that slot. After a Dock restart, code returns to its old slot instead of shuffling.

Ordinal pass

Workspaces still missing claim the first unclaimed space on their desired display, else the first remaining space in position order. Lowest ordinal takes lowest position. No HashMap order leaks in.

Layout state follows the logical name

apply_remap_moves moves each BSP tree from from to to. A stale dynamic binding with from == to drops its tree so a dead SpaceId never keeps state. Save writes workspace trees under the stable workspace name in workspace_layouts and keeps leftover raw SpaceId keys only for unmanaged spaces. Load restores trees onto current backings. Writes are atomic: temp file, fsync file, rename, fsync directory.

Pending queues that stop races

  • pending_workspace_focus and pending_workspace_move: FIFO queues so fast alt-2 then alt-3 cannot overwrite. Focus fires once when the backing materializes, then the entry is dropped so later alt-tabs are not hijacked.
  • awaited_creations plus pending_creations: one in flight creation at a time. Binding picks a new unclaimed space on the anchor display that was absent in the before set. Pre existing spaces are never adopted.
  • pending_close: a closing window leaves placements at once but stays in the BSP until observation confirms destruction. Cancel keeps the tree stable.
  • pending_destroy: workspace and layout stay until a complete snapshot proves the space is gone.
  • dynamic_grace: two second immunity after a dynamic spawn so async focus and window arrival are not judged empty.
  • space_cursors: HashMap DisplayId to (SpaceId, pending): optimistic per display cursor. Next, previous, explicit, and workspace focus update it. Snapshots confirm or reconcile it.

7. Layout is pure math

Crates rovr-layout and rovr-core/src/layout.rs, bsp.rs, layout_state.rs. Same rule as PRODUCT.md: layout code never touches Accessibility, SkyLight, FFI, or Platform.

input:  usable area + ordered WindowIds + config (gap, padding, ratio)
output: WindowId -> Rect
compute(kind, LayoutRequest { area, windows, gap, padding, split_ratio })
  • apply_layout clears desired.space and rebuilds it from rules each cycle, then writes frames per workspace layout, plugin override, scratchpad filter, and insets_off session toggle.
  • BSP ops: rotate, mirror, balance, swap, warp, set_ratio, directional swap and warp from observed geometry.
  • WASM plugins load from ~/.config/rovr/plugins/*.wasm. Each call carries fuel plus memory caps. validate_placements rejects empty, duplicate, missing, foreign, NaN, infinite, zero, negative, or huge frames and falls back to the built in layout.
  • Fresh BSP inserts target exact 50 percent ratios. Balance resets drifted persisted ratios.

8. Config: parse, validate, compile, commit

File: rovr-config/src/lib.rs. Native format is TOML at config-version = 1. Missing key means 1. Anything else fails before partial reconfig.

[general] layout gap padding reconcile_on_wake reconcile_interval_ms plugin
[focus] follows_mouse
[animations] enabled duration_ms curve
[[workspace]] name layout display persistent plugin
[[rule]] app title workspace float target_workspace opacity layer
[[scratchpad]] name app title
[[bind]] key command   # skhd syntax key, CLI style command
  • Validation rejects negative gap and padding, empty or duplicate workspace names, unknown workspaces in rules, bad opacity, bad regex, empty or duplicate binds, bad hotkey keys, and bad bind commands.
  • compile_rules compiles each app and title regex once per load and keeps config order. Predicate is all_of: every selector must match. Empty predicate matches every window.
  • Binds are the single source of truth for the built in listener and config gen-skhd output. Key syntax uses skhd chords such as alt - h. Command syntax must parse with the same parse_command the CLI uses, so window --focus 1 fails at load instead of drifting at runtime.
  • Reload is transactional. Only affected state is disturbed. Ordinal identity is preserved across reorder and manual drags.

10. Platform boundary

Crate rovr-platform. The trait is small. The macOS implementation is where the private API knowledge lives.

trait Platform: Send {
  fn capabilities() -> Capabilities;
  fn snapshot(&mut self) -> Result<PlatformSnapshot, PlatformError>;
  fn execute(&mut self, action: &Action) -> Result<(), PlatformError>;
  fn needs_refresh() -> bool;                       // default false
  fn snapshot_wedged_ms() -> Option<u64>;             // doctor visibility
  fn drain_diagnostics() -> Vec<PlatformDiagnostic>;
  fn sa_reinject_diagnostics() -> Option<SaReinjectDiag>;
  fn set_event_watcher(watcher: Arc<dyn Fn(u32)>);   // AX wake kinds
}

Mock for tests

mock.rs returns a canned snapshot, records executed actions, and reports full capabilities except the scripting addition. This lets reconciler, layout, config, IPC, and recovery tests run without WindowServer, on any OS.

BoundedWorker: one thread, no pile up

File: bounded_worker.rs. AX and SkyLight calls can hang when an app dies mid call or the Dock restarts. The old spawn and abandon pattern leaked one thread per hang. Now one worker thread serves one job at a time with a bounded wait.

macOS snapshot path

File: macos/mod.rs. Roughly this order per snapshot:

  1. Enumerate window candidates through the C bridge into BridgeWindow structs.
  2. Collect pids that need AX refinement. Refine per pid on persistent pid keyed workers with a shared 500 ms deadline. Map 0, 1, other to No, Yes, Unknown.
  3. Fall back to SkyLight managed state for background apps where AX stays Unknown, using window level and parent checks from yabai practice.
  4. Enumerate displays and spaces. Keep one focused space per display. Never collapse to a global focused space.
  5. Derive display_id from the space to display map built once per snapshot, not rect hit testing.
  6. Resolve window to space in bulk per space instead of one private API call per window, which cut about 100 round trips and dropped observe time from hundreds of ms to about 100 ms.
  7. Fill minimized unknowns from last known values so tiling does not flap.

macOS execute path

  • Refresh actions never touch macOS. All other actions first ensure the bridge is idle so a mutation cannot overlap a timed out observation closure.
  • Frame, focus, minimize, close, and fullscreen go through per pid AX workers. Focus on another space first focuses that space through the normal path, then waits bounded for WindowServer to land before raising.
  • Space create, destroy, and reorder plus layer, sticky, shadow, opacity, and scale go through the scripting addition client with capability gating. Absent capability returns Unsupported instead of failing each cycle.
  • Space focus prefers the scripting addition with a 30 by 100 ms retry for Dock catch up, then falls back to a bridge swipe gesture with a bounded 450 ms settle gate. Cross display posts skip the gate. Step posts one high velocity swipe pair per displacement without querying current space.

11. Daemon threads and latency fixes

File: rovr-daemon/src/main.rs. The state loop owns the engine and the platform. Every other thread sends it envelopes.

Envelope

Envelope { request: Request, response: Sender<Response>,
  queued_at: Instant, event_wake: bool }

AX callbacks share one atomic RefreshWake. Created and destroyed kinds enqueue one Refresh for instant spawn tiling. The wake is acknowledged before its snapshot so callbacks during observation queue the next wake instead of merging silently.

Why switches got fast

History detail: space_history tracks current and previous per display for focus-recent. Active display fallback is focused, then main, then lowest id.

12. CLI: a thin client

File: rovr-cli/src/main.rs. The CLI parses flags, builds one Request, sends one line of JSON, prints the pretty response. Policy stays in the daemon.

rovrd --foreground
rovr ping | doctor | query windows | query spaces | debug events
rovr window focus 1 | window focus-direction west 1
rovr space focus 3 | workspace focus code | layout rotate
rovr config dump | config dump --full | config check PATH | config reload
rovr subscribe            # Hello, then Heartbeat + StateChanged stream
rovr sa status | sa install | sa uninstall
  • Request ids come from an atomic counter. Responses have a 5 s deadline and a 1 MiB cap with bounded line reads.
  • completions, config dump, and gen-skhd run locally without IPC.
  • 39 binds expressible in Rovr now live as in process [[bind]] entries. skhd keeps app launches, reload, chained resizes, and space destroy.
  • Artifact discovery canonicalizes current_exe first so symlinked installs such as ~/.local/bin/rovr still find payload, loader, and helper next to the real binary or under prefix lib paths.

13. Scripting addition stack

Private Space lifecycle and cosmetics live here. The design keeps privilege small and observable.

rovr-sa-payload: the code in DockObjC dylib on /tmp/rovr-<uid>/sa.sock with rovr-sa-2.0 handshake and honest capability bits. SkyLight cosmetics direct. Space lifecycle via vendored yabai MIT pattern tables with attribution. Scan bounds guarded. arm64e build with loader caps patched 0x81 to 0x80 per yabai issue 2686.
rovr-sa-loader: the injectorRoot only. Adapted from yabai loader.m with attribution. Stable signing with a cert anchored designated requirement keeps the Accessibility grant across rebuilds. Embedded Info.plist in __TEXT,__info_plist lets TCC attribute launchd spawned rovrd.

Helper: the smallest possible root service

Crate rovr-sa-helper plus platform/macos/reinject.rs. LaunchDaemon com.rovr.sa-helper owns /var/run/rovr-sa-helper.sock and starts on demand. The wire frame is fixed {magic, proto, opcode, uid}. There are no pid, path, command, or env fields by construction. Each use validates fixed root owned artifacts with lstat plus O_NOFOLLOW, root owner, and safe modes. Auth checks getpeereid equals request uid equals /dev/console owner. The daemon calls exactly inject and status with fixed argv and minimal env. SMAppService cannot serve here because it needs an app bundle path. The launchd fallback is documented in docs/SA.md. No sudoers file anywhere.

Five honest SA states

not_installed | installed_not_injected | injected_compatible
| incompatible_protocol | capability_missing

sa install writes files, registers the service, injects directly, polls the handshake, writes payload.installed.json with sha256 plus handshake version, then reports per capability bits for create, destroy, reorder, focus, opacity, layer, sticky, shadow, and scale. sa uninstall removes bootout first, then plist, helper, loader, payload, marker, and socket, then restarts Dock because mapped code cannot be evicted any other way. Client framing uses len = 3 + payload_len with the socket keyed on getuid to match the payload.

14. Recovery and observability

Rovr assumes it will be surprised and keeps the evidence.

  • FlightRecorder in core/src/flight_recorder.rs: bounded ring, default 2048 records, each with sequence, unix ms, kind, and detail. Records events, actions, remap moves, creations, destroys, and platform errors. rovr debug events reads it.
  • rovr doctor: protocol version, capabilities, SA socket plus version plus attribs, reinject phase plus generation plus attempts plus retry, wedge ms, generation, counts, config path, layout, gap, interval.
  • Recovery triggers that force scoped or full re-observation: wake, Dock restart, display change, space change, suspicious mutation failure. Every OS wait has a deadline. No infinite polling.
  • Persistence in core/src/persistence.rs: layouts, workspace owned trees, scratchpads, workspaces. Atomic replace with fsync on file and directory survives crash and power loss mid save.
  • Hotkeys: main thread manager, one persistent bounded FIFO dispatcher, every IPC response read. Invalid bind command at runtime logs and runs nothing.
  • Signing detail that matters: stable cert anchored requirement plus embedded plist keep TCC and Accessibility grants stable across rebuilds.
Mental model for debugging. Query state to see both models. Read debug events for the seconds before a failure. Check doctor for wedge, SA, and reinject state. If observed and desired differ after an action, the next reconcile already carries the retry.
